# Design: 課程講義列印（Save course detail as PDF）

Generated by /office-hours on 2026-10-21
Branch: worktree-feature-course-pdf
Repo: ying0515/cms-1019
Status: APPROVED（/autoplan 最終 gate 2026-10-21 核准；本文已併入 eng R1–R4、CEO、Design DS*、DX*、Eng EN* 與 gate 決定，審查過程見下方 Review record）
Mode: Startup（公司內部專案）

## Problem Statement

課程開班時需要發給學員／講師一份紙本課程講義。內容（課程目標、大綱、先備知識等）已經在 CMS 裡，但目前沒有可直接列印的版型。

## Demand Evidence

- 有人明確開口要這個功能（使用者回答「有人明確開口要」）。
- 尚未記錄：開口者的職稱、每週需要印幾門課。列在 Open Questions，上線前的驗收（UC1）會一併問清楚。

## Status Quo

目前從公開網站（`uuu.com.tw/Course/Show/...`）的課程頁直接用瀏覽器列印，版面很亂。內容本身沒問題，痛點在排版。

## Target User & Narrowest Wedge

- 讀者：學員與講師（紙本講義）。操作者：後台人員，在課程檢視頁按按鈕列印。
- 最窄切入點：使用者已確認「列印視窗就可以」，用瀏覽器的「另存為 PDF」即可，不需要一鍵下載 .pdf 檔。

## Constraints

- 前後端都不新增 PDF 套件，不嵌入中文字型（系統字型處理繁中）。
- 只處理單一課程，不做批次匯出（#16）。
- 檢視頁的螢幕畫面只多一行列印提示（UC3），其餘不變。
- UI 文字使用繁體中文。
- 列印規則刻意設為全站生效：在任何後台頁面按 Ctrl+P，都會隱藏側欄、`p-button`、toast、確認對話框、tooltip，並取消外殼的內距與最小高度。後台頁面印出來本來就不需要這些元素，所以這是預期中的改善，不是副作用。`[pButton]`、對話框遮罩、分頁器不在隱藏範圍內（d10，等有第二個列印畫面再處理）。

## Premises（已確認）

1. 讀者是學員／講師。講義只放：課程名稱、官方課程名稱、簡介代碼、時數、原廠、8 個課程內容欄位（空值不印）、相關認證，以及指向公開課程頁的 QR code。不放主代碼、友善網址、顯示順序、上架狀態／日期、定價、點數、課程群組、職務類別。
2. 交付方式是瀏覽器原生列印：按鈕 → `window.print()` → 使用者選「另存為 PDF」。
3. 只處理單一課程，批次不在範圍內。
4. 在後台做，而不是修公開網站：公開網站不在這個 repo；後台資料最新。尚未上架的課也能印，講義上改印替代文字，不印會連到錯誤頁的 QR（UC2）。
5. 檢視頁的螢幕畫面只新增「列印講義」按鈕與一行列印提示，其餘不變；列印時才切換成講義版型。

## Approaches Considered

- **A 檢視頁直接加列印樣式**：不採用。用黑名單（`.no-print`）隱藏內部欄位，之後在後台新增的欄位會預設被印給學員。
- **C 獨立講義路由 `/courses/:id/handout`**：不採用。為了螢幕預覽，必須改 `app.html` 外殼（目前一律渲染側欄），成本和風險都較高。
- **D 改公開網站課程頁的列印樣式**：不在這裡做（d2）。理由：(1) 公開網站不在這個 repo，排程與部署不歸我們；(2) 公開頁只顯示已上架課程，開班前要印的課可能還沒上架；(3) 公開頁有導覽、行銷區塊，要另外做白名單才能保證只印學員需要的內容。已開 #20 通知公開網站負責人，避免兩邊各自維護列印版面。

### 講義版面（A4 直式）

```
┌──────────────────────────────────────────────┐
│ {title}                              ┌──────┐│
│ {officialTitle}（有值才顯示）            │ QR   ││
│ 簡介代碼 {courseId}｜時數 {hour} 小時       │ code ││
│ 原廠 {partner.name}（有值才顯示）         └──────┘│
│                               掃描查看課程網頁  │
├──────────────────────────────────────────────┤
│ 課程目標 / 適合對象 / 先備知識 / 課程大綱 /        │
│ 考試／認證說明 / 教材 / 備註 / 其他資訊           │
│ （保留換行；空值整段略過）                        │
│ 相關認證                                       │
│ • {partnerName} - {title}（空的話整段略過）       │
└──────────────────────────────────────────────┘
```

- 內容欄位依閱讀順序（DS1）：課程目標、適合對象、先備知識、課程大綱、考試／認證說明、教材、備註、其他資訊。順序以 `HANDOUT_CONTENT_KEYS` 為準。
- 標題列：`courseId` 去頭尾空白；時數 ≤ 0 時不印「｜時數 N 小時」（DS4）。
- Null 處理：`partner` 為 null 時，整行「原廠」不印。認證的 `title` 為 null 時，只印 `partnerName`，後面不接「 - 」。這是講義自己的格式化函式，不改 `CourseDetail.certificationLabel()`。
- QR 區塊寬 34mm，canvas 內本來就畫有 courseId；下方印講義自己的說明「掃描查看課程網頁」（DS5），不印公開網址。
- 字體排版（DS7）：正文 11pt、行高 1.6，h1 18pt、h2 13pt，墨色 #000，標題列下方 1px 實線，字型沿用全域 body 字型（`'Noto Sans TC', 'Microsoft JhengHei', …`）。標題只靠字級與粗細區分，不用顏色或底色。
- 分頁（R4、DS8）：長文字 `white-space: pre-wrap`，`orphans: 3; widows: 3`；`h2 { break-after: avoid }`；認證項目 `break-inside: avoid`；標題列 `break-inside: avoid`。不設 `overflow: hidden`／`max-height`／字級縮放，長內容自然分頁，不承諾頁數。
- 沒有內容欄位也沒有認證的課程，照樣只印標題列與 QR（d6），不加填充文字。

### 列印規則

`src/styles.scss`（全域）：

```scss
.print-only { display: none; }

@media print {
  @page {
    size: A4; margin: 15mm;
    @top-center { content: ''; }                                        // 壓掉瀏覽器頁首（UC4）
    @bottom-center { content: counter(page) ' / ' counter(pages); … }   // 頁碼，同時壓掉瀏覽器頁尾的網址
  }
  body { background: #fff; }
  p-toast, p-confirmdialog, p-button, .p-tooltip, .screen-only { display: none !important; }
  .print-only { display: block; }
}
```

`src/app/app.scss`（外殼，同一個 encapsulation scope；**附加在檔案最末端**，宣告加上 `!important`，即使 A4 可列印寬度讓 768px 規則跟著生效，列印規則仍然會贏）：

```scss
@media print {
  .sidebar { display: none !important; }
  .layout { display: block !important; min-height: auto !important; } // 避免多印一張空白頁
  .content { padding: 0 !important; margin: 0 !important; }
}
```

- `p-button` 全域隱藏，QR 元件裡的「下載 QR Code」按鈕不會被印出來。
- `.p-tooltip` 隱藏（EN1）：tooltip 掛在 body 上，滑鼠點按鈕時正好顯示，不隱藏會被印進講義。

### 列印動作

```ts
print(): void {
  const item = this.item();
  if (!item) return;
  // 在按鈕當下讀取：元件建構早於 router 的 TitleStrategy 更新標題（R1）
  const pageTitle = document.title;
  document.title = `${item.courseId.trim() || item.title.trim()}-課程講義`; // 「另存為 PDF」的預設檔名（DX4）
  try {
    window.print();                       // Chrome/Edge 會阻塞到列印視窗關閉（P7，人工驗證）
  } catch {
    this.messages.add({ severity: 'error', summary: '無法開啟列印視窗', detail: '請改用 Ctrl+P 列印' });
  } finally {
    document.title = pageTitle;           // 一律同步還原，不依賴 afterprint（DX2）
  }
}
```

- 不用 `afterprint` 監聽器，所以不會在 `afterprint` 沒觸發時留下錯誤的標題，也不會重複疊加監聽器。
- 直接按 Ctrl+P 一樣會印出講義版型（由 CSS 控制），只是 PDF 預設檔名是一般的頁面標題。這是可以接受的限制（d1 維持 R1/D4）。
- 瀏覽器擋下列印時通常不會丟例外，toast 是保險；`finally` 保證標題一定還原。

### 列印提示（UC3）

- 「列印講義」按鈕保留 `pTooltip`「列印時請取消勾選「頁首和頁尾」」。
- 課程載入後，標題列下方常駐一行提示：「列印講義時，請在列印視窗取消勾選「頁首和頁尾」，以免印出系統網址。」（`data-testid="print-hint"`，只在螢幕上顯示）。tooltip 只有滑鼠停留才看得到、螢幕閱讀器也讀不到，所以加常駐提示。
- 瀏覽器的列印預覽就是唯一的預覽，不另做螢幕預覽。

### 重用

- `CourseQrCode`：講義內放第二個實例，指向同一個公開網址，`showCaption=false`。
- 資料：沿用檢視頁已經載入的 `item()`（`CourseService.getById`，含認證），不再呼叫 API。`CourseHandout.course` 的註解寫明列表資料不適用（DX6）。

### QR 行為（UC2）

公開課程頁打得開才印 QR，避免紙本講義上的 QR 連到錯誤頁。規則（使用者 2026-10-21 確認）：`publishStatus.isPublished` 為真，且 `scheduleOn ≤ 今天 ≤ scheduleOff`（本機日期）。否則在 QR 的位置改印「課程網頁上架後，可至 uuu.com.tw 查詢本課程」。

- 「今天」在 `beforeprint` 時重新取得並立即重繪講義（按鈕與 Ctrl+P 都會觸發），分頁開過夜再列印也以列印當天判斷（PR #23 審查）。
- 公開網址需要簡介代碼，所以簡介代碼空白時也改印替代文字；標題列的「簡介代碼」與「時數」各自為空時略過，兩者皆空則整行不印。

- 後端：`PublishStatusLookup` 新增 `IsPublished`，課程查詢（`CourseRepository` 的 JOIN）與 `GET /api/lookups/publish-statuses` 都帶出這個欄位；fake 與 API 測試一併更新。
- 測試：`course-handout.spec.ts` 以草稿狀態、已過下架日、尚未到上架日三種情況，斷言不印 QR、改印替代文字。

### 測試（Karma/Jasmine）

- `course-handout.spec.ts`：
  - 渲染 title、官方名稱、標題列、原廠、QR；`officialTitle`、`partner` 為 null 時整行略過。
  - 時數 0 時不印時數；`courseId` 去頭尾空白（DS4）。
  - QR 無 figcaption，另有「掃描查看課程網頁」說明（DS5、DX5）。
  - 內容欄位以 8 個欄位都有值的 fixture，斷言依閱讀順序的字面清單渲染（DS1、EN2）；大綱保留換行；空白欄位略過。
  - 每個 `CONTENT_FIELDS` key 剛好出現在 `HANDOUT_CONTENT_KEYS` 或 `HANDOUT_EXCLUDED_KEYS` 其中之一（EN2）。
  - 講義自己的文字（排除 QR 子元件）不含後台標籤「主代碼」「友善網址」「顯示順序」「上架狀態」「上架日期」「下架日期」「定價」「點數」，也不含 fixture 的特徵值。
  - 認證 `title` 為 null 時不出現結尾「 - 」；沒有認證時整段略過。
- `course-qr-code.spec.ts`：`showCaption=false` 時沒有 figcaption（預設值由既有網址斷言涵蓋）。
- `course-detail.spec.ts`：
  - 講義以 `print-only` 渲染在 `.screen-only` 之外；找不到課程時沒有講義、按鈕與提示。
  - 按鈕帶 tooltip，`.screen-only` 內有常駐提示（UC3）。
  - `print()`：列印當下標題為 `{courseId}-課程講義`，之後還原；還原的是按下當下的標題，連按兩次也正確（R1）；`courseId` 空白時改用課名（DX4）；`window.print` 丟例外時標題還原並顯示錯誤 toast（DX2）；點按鈕會呼叫 `window.print`。
  - 既有斷言原樣通過；QR 面板的查詢限定在 `.screen-only` 內（EN6）。

## Success Criteria

- 開口要的人在課程檢視頁按一個鈕，30 秒內拿到一份可以印的講義 PDF。
- **上線前驗收（UC1）**：請開口要的人用一門真實課程實際印一次，確認欄位與版面符合需要（對照 Open Questions 1–3），記錄回饋後才正式上線。
- 不洩漏內部資訊（d4）：「洩漏」指 CMS 網址、後台路徑與內部標籤／欄位值。講義元件內容由單元測試保證；匯出的 PDF 不含 CMS 網址由人工驗證（列印視窗取消勾選「頁首和頁尾」後檢查）。公開 QR 網址裡的 pkid 是公開資訊，不算洩漏。
- 可讀、不截斷（R4）：人工驗證挑 3 門真實課程（含內容最長的一門），Chrome、Edge 列印預覽正文 ≥10pt、中文顯示正確、內容無截斷、標題不孤懸在頁尾。
- 檢視頁的螢幕畫面除了按鈕與提示外不受影響：既有 `course-detail.spec.ts` 斷言原樣通過（repo 沒有 E2E 框架）。
- 人工驗證清單（T4，Chrome 與 Edge）：
  - 講義右上角 QR 有圖、下方有說明文字；未上架課程印替代文字（UC2）。
  - 用滑鼠點「列印講義」後，預覽中沒有 tooltip（EN1）；PDF 預設檔名是 `{courseId}-課程講義`，關閉視窗後分頁標題還原（P7）。
  - 沒有內容欄位的課程：只印標題列與 QR（d6）。
  - 列表頁與表單頁按 Ctrl+P：除了按鈕被隱藏，版面沒有壞掉；講義最後沒有多一張空白頁（EN4）。
  - 檢視頁在窄螢幕與 200% 縮放下，標題列按鈕會換行、不重疊；鍵盤 Tab 到「列印講義」有焦點框，Enter 開啟列印，關閉後焦點回到按鈕（DS11）。
- **`@page` 實驗（UC4，限時 30 分鐘，取代 d5）**：在 Chrome、Edge 試 margin box 的頁碼與課名頁尾，以及 `@page { margin: 0 }` 能否壓掉瀏覽器的頁首頁尾。結果記在本文件；可行就另案採用，不可行就維持提示。
  - **結果（2026-10-21，headless Chrome 與 Edge `--print-to-pdf`，保留瀏覽器頁首頁尾）**：
    - 對照組：頁首印日期與分頁標題，頁尾印 `http://localhost:4300/courses/3340` 與頁數，證實 P8（網址含 pkid）。
    - 只加 `@bottom-center { content: counter(page) ' / ' counter(pages) }`：瀏覽器頁尾（含網址）消失，改印「1 / 1」；瀏覽器頁首（日期、標題）仍在。
    - 再加空的 `@top-center { content: '' }`：瀏覽器頁首也消失。兩個瀏覽器結果相同。
    - 結論：定義 margin box 就能壓掉瀏覽器頁首頁尾，不必依賴使用者取消勾選，還多了頁碼。margin box 預設是襯線字型，採用時要指定字型。尚未在互動式列印視窗確認；`margin: 0` 方案因 margin box 已可行而未測。使用者決定採用（2026-10-21）：全域 `@page` 加上 `@top-center`（空）與 `@bottom-center`（頁碼），常駐提示與 tooltip 保留當保險。採用後以長課程（7 頁）在 Chrome、Edge 重印確認：每頁印「n / 7」，沒有瀏覽器頁首頁尾。
